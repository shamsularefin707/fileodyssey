# M2 — Images Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real image tools: convert between formats, resize, compress (including a target-size mode), combine images into one PDF, and read QR/barcodes from image files. Each tool comes with a fidelity report, works on desktop and Android, and gets per-tool options in the UI.

**Architecture:** `fo-core::image` has three parts:
- `decode`: path → `Decoded` (frames + ICC + EXIF + bit depth + alpha), with EXIF orientation applied.
- `encode`: `Decoded` + target + options → file + notes.
- `ops`: resize and the target-size search.

Four `Tool` impls (`img.convert`, `img.resize`, `img.compress`, `qr.read`) and one combining tool (`img.to_pdf`, multiple inputs → one output) register in `AppState`. `ToolInfo` gains `options: Vec<OptionSpec>`, which the UI renders generically.

**Tech Stack:**
- Already in use: `image` 0.25.10 (no default features; formats bmp dds exr ff gif hdr ico jpeg png pnm qoi tga tiff webp).
- New: `ravif` 0.13 (no default features, so no asm), `webp` 0.3 (libwebp via cc; lossy and animated WebP), `jpeg-encoder` 0.7, `oxipng` 10 (no default features), `fast_image_resize` 6, `jxl-oxide` 0.12 (decode), `zune-jpegxl` 0.5 (lossless encode), `resvg` 0.50, `psd` 0.3, `rawler` 0.8, `rxing` 0.9 (features `encoding_rs`, no `image`), `pdf-writer` 0.15. The spike built all of these together on 2026-11-19.

**Spec:** `docs/superpowers/specs/2026-11-19-fileodyssey-toolkit-design.md` (§5.2, §6.4, §7) · Roadmap: `docs/superpowers/plans/2026-11-19-roadmap.md`

## Global Constraints

- Everything from M1's Global Constraints still applies: offline, never overwrite, no leftover temp files, untrusted inputs, all strings in `strings.rs`, and clippy/fmt clean.
- **No C build steps that need cmake, meson or nasm.** The only C dependency allowed is libwebp (via `cc`), because it cross-compiles for Android with the NDK.
- Read formats: PNG, JPEG, GIF (all frames), BMP, ICO, TIFF, WebP (incl. animated), JPEG XL, SVG, PSD (flattened), camera RAW, TGA, DDS, HDR, EXR, QOI, PNM.
- Write formats: PNG, JPEG, WebP, AVIF, JPEG XL (lossless), GIF, BMP, ICO (multi-size), TIFF, TGA, QOI, PNM, PDF.
- Reading AVIF/HEIC and rasterising PDF pages are **out of M2** (ruled below; the UI says "No tools for this file type yet" for them).
- **Pixel limit:** refuse any image over 300 megapixels (per frame) or with more than 1,000 frames, with the message "This image is too large to open safely (N megapixels)".
- Defaults: quality 90, keep metadata on, JPEG background white.
- **Fidelity report on every output.** Metrics are `Width`, `Height`, `Frames`, and `Bit depth` (before → after). Warnings cover:
  - alpha flattened;
  - animation dropped;
  - bit depth reduced;
  - metadata dropped;
  - lossy re-encode ("Saved with lossy compression at quality N").

  Lossless re-encodes with no drops are `Exact`.

## Rulings (made at plan time)

- AVIF/HEIC **reading** goes to M8. On Android it uses the system `ImageDecoder`; for desktop we pick a pure-Rust decoder or dav1d then. Cost if wrong: users can't convert AVIF/HEIC until M8.
- JPEG XL **writing** is lossless only (`zune-jpegxl`), because libjxl needs cmake. Cost: JXL output files are larger than lossy JXL would be.
- RAW is developed with rawler's default pipeline (no user controls). Cost: colours may differ from the camera's own JPEG.
- The PDF output embeds JPEG sources byte-for-byte (DCTDecode) and everything else as Flate RGB/RGBA. Cost: none.

## Review Focus

1. **Phone photos with EXIF orientation 6/8** must come out upright in every format. → Task 1 test.
2. **Transparent PNG → JPEG** must be flattened onto white with a report warning, never black. → Task 2 test.
3. **Huge or decompression-bomb images** must be refused with a clear message, not exhaust memory. → Task 1 test.
4. **Animated GIF → PNG/JPEG** gives the first frame plus a warning; **GIF → WebP/GIF** stays animated. → Task 2 tests.
5. **Corrupt or truncated images** give `Failed` with "Couldn't read this image: …", never a panic. → Task 1 test, plus the panic guard from M1.

### Task 2: Encode with fidelity notes

**Files:**
- Create: `crates/fo-core/src/image/encode.rs`
- Test: `crates/fo-core/tests/image_encode.rs`

**Interfaces:**
- `pub struct EncodeOpts { pub quality: u8, pub keep_metadata: bool, pub lossless: bool }`, `Default` = 90 / true / false
- `pub fn encode(d: &Decoded, target: &str, opts: &EncodeOpts, out: &Path) -> Result<FidelityReport, ToolError>`
- `target` ∈ `png jpg webp avif jxl gif bmp ico tiff tga qoi pnm pdf`; anything else → `Failed("Can't save images as .<x>")`
- Rules:
  - single-frame targets keep frame 0 and warn "Animation dropped: kept the first of N frames";
  - targets without alpha (jpg, bmp-24, pnm) flatten onto white and warn "Transparency replaced with white";
  - 16-bit sources keep 16 bits for png/tiff and otherwise warn "Colour depth reduced from 16 to 8 bits";
  - ICC and EXIF are written for jpg (jpeg-encoder app segments), png (iCCP/eXIf via the png encoder) and webp (when supported); otherwise warn "Metadata (EXIF/colour profile) not kept in .<x>" if any existed;
  - lossy targets (jpg, avif, webp unless `lossless`) warn "Saved with lossy compression at quality N".
  - ICO writes sizes 16, 32, 48, 256 (clamped to the source size).
  - PDF writes one page per frame, sized at 72 dpi in pixels. A JPEG source is embedded unchanged (pass the original bytes through `Decoded::source_bytes: Option<Arc<[u8]>>`, added in this task).
  - GIF and WebP write all frames with their delays.

- [ ] **Step 1: Failing tests:**
  - `png_to_png_is_exact`
  - `transparent_png_to_jpg_flattens_to_white` (corner pixel ≈ white, and the warning is present)
  - `gif_to_png_keeps_first_frame_and_warns`
  - `gif_to_webp_stays_animated` (decode output → 3 frames)
  - `sixteen_bit_png_to_tiff_keeps_16` / `..._to_jpg_warns_depth`
  - `jpeg_exif_kept_in_jpg_output`
  - `every_target_produces_a_decodable_file` (loop over all targets except pdf; decode each back; dimensions match)
  - `pdf_output_starts_with_pdf_header_and_has_n_pages` (count `/Type /Page` occurrences)
  - `unknown_target_fails_clearly`
- [ ] **Steps 2–4:** FAIL → implement → PASS. **Step 5: Commit** `feat(core): image encoding to all write formats with fidelity notes`.

### Task 3: Image tools and option specs

**Files:**
- Modify: `crates/fo-types/src/lib.rs` (add `OptionSpec`, `OptionKind`; `ToolInfo.options: Vec<OptionSpec>` with `#[serde(default)]`)
- Create: `crates/fo-core/src/image/{ops.rs,tools.rs}`, `crates/fo-core/src/qr.rs`
- Modify: `crates/fo-app/src/state.rs` (register the tools)
- Test: `crates/fo-core/tests/image_tools.rs`, plus `fo-types` serde test

**Interfaces:**
- `pub enum OptionKind { Slider { min: u32, max: u32, step: u32, default: u32, unit: String }, Toggle { default: bool }, Number { min: u32, max: u32, default: u32, unit: String }, Choice { choices: Vec<(String, String)>, default: String } }`
- `pub struct OptionSpec { pub key: String, pub label: String, pub kind: OptionKind, pub targets: Vec<String> }` (empty `targets` = shown for every target)
- `ops::resize(img: &DynamicImage, spec: &ResizeSpec) -> DynamicImage`, where `pub enum ResizeSpec { Exact { w: u32, h: u32 }, Percent(u32), Fit { w: u32, h: u32 } }`. Lanczos3 via `fast_image_resize`. Fit never upscales.
- `ops::encode_to_size(d: &Decoded, target: &str, max_bytes: u64, out: &Path) -> Result<FidelityReport, ToolError>`: binary search on quality 10..=95 (at most 7 tries). If even quality 10 is too big, keep that result and warn "Couldn't reach N KB; smallest is M KB". Lossless targets fall back to `oxipng` (png) or a plain encode, plus the same warning.
- Tools (`pub fn image_tools() -> Vec<Arc<dyn Tool>>`, all with platforms Desktop + Android):
  - `img.convert` (Images; targets = the write list; options `quality` Slider 1–100 default 90 for jpg/webp/avif, `keep_metadata` Toggle true)
  - `img.resize` (Images; targets = the write list minus pdf, with `same` first meaning the source format; options `mode` Choice fit/percent/exact default fit, `width` Number 1–30000 default 1920 px, `height` Number default 1080 px, `percent` Number 1–400 default 50 %)
  - `img.compress` (Compress; targets `same`, jpg, webp, avif; options `max_kb` Number 0–100000 default 0 meaning "use quality", `quality` Slider default 80). `same` for PNG → oxipng level 4 lossless.
  - `qr.read` (Images; target `txt`; writes one decoded text per line; report metric `Codes found`; zero codes → warning "No QR code or barcode found"). Uses `rxing` with a `Luma8LuminanceSource` built from `to_luma8()` and multi-barcode reading.
- Report metrics added by every tool: `Width`, `Height`, `Frames`, `Bit depth`, and for compress `File size (KB)`.

  - `resize_fit_never_upscales`
  - `resize_percent_halves`
  - `compress_to_target_size_meets_budget` (noise image 512², `max_kb`=40 → output ≤ 40 KB)

**Interfaces:**
- For a combining tool, the runner processes all inputs as **one** unit:
  - the event `input` = the first input path;

- `img.to_pdf`: Images; target `pdf`; options `page` Choice image/a4/letter default image. A4/Letter fit each image centred with 10 mm margins. Report metric `Pages` = number of inputs.
