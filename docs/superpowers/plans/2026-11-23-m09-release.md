# M9 — Release pipeline, updater, docs → v1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** Ship v1.0.0 on GitHub Releases: Windows NSIS + MSI, Linux AppImage + .deb, signed Android APKs; desktop self-update through signed manifests, Android "new version available"; README download docs.

**Architecture:** `release.yml` (tag `v*` or manual run → draft only) creates a draft release, builds desktop bundles with `tauri-action` (updater artifacts + `latest.json`, NSIS preferred on Windows), builds per-ABI release APKs signed with a PKCS12 keystore from secrets (Gradle signing patched in after `tauri android init`), adds `SHA256SUMS`, then publishes (tags only). `fo-app/src/update.rs`: settings (`check_updates`, `skipped`), desktop check/install via `tauri-plugin-updater`, a fixed release-page opener. The UI checks at start when allowed (desktop: updater; Android: GitHub API from the webview) and shows a banner; an About section holds the version, the switch and Check now.

**Spec:** §8, §9 (only network use is the optional update check), §11 step 9.

## Global Constraints
- The update check is the only network use and can be turned off; nothing is downloaded without a tap.
- Android never self-installs: it links to the release.
- No public pre-releases: trial runs make drafts only.
- Secrets: TAURI_SIGNING_PRIVATE_KEY(_PASSWORD), ANDROID_KEYSTORE_BASE64, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS.

## Review Focus
1. Offline or GitHub unreachable: the check fails quietly (no error banner), the app works.
2. "Not now" on 1.0.1 isn't asked again for 1.0.1, but is for 1.0.2.
3. Version compare: 1.0.10 > 1.0.9; "v1.1.0" tags; pre-release tags ("1.1.0-beta") never offered.
4. CI without signing secrets still builds (updater artifacts only in the release workflow).
5. Release minification (R8) must not strip the plugins' Kotlin classes.
