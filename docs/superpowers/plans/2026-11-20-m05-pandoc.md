# M5 — Pandoc conversions & fidelity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Convert between MD (Pandoc/GFM/CommonMark), HTML, DOCX, ODT, EPUB, RTF, TXT, LaTeX, RST, Org and AsciiDoc on every platform with a fidelity report on each result; CSV↔JSON and CSV→XLSX; DOCX/ODT/RTF in the reader; a golden corpus with round-trip tests gating CI.

**Architecture:** Spike result (ledgered): the official `pandoc.wasm` 3.10 uses legacy wasm exceptions, which wasmtime cannot run (and its 58 MB module took ~100 s to compile); every target webview runs it. So Pandoc runs in a Web Worker inside the app's webview. Rust keeps the job model: `fo-core::pandoc::PandocEngine` is a trait; `DocConvert` (a normal `Tool`) calls it three times (convert, input→AST, output→AST) and builds the report from the two ASTs. `fo-app` implements the trait with a bridge (event `pandoc-request` → UI pulls a binary frame with `pandoc_take` → worker → `pandoc_done` raw body). Tests and the corpus use `NativePandoc` (same 3.10 release as a binary).

**Tech Stack:** pandoc 3.10 (wasm + linux binary from jgm/pandoc releases), `@bjorn3/browser_wasi_shim` + pandoc-wasm `core.js` (MIT) bundled with esbuild into a committed worker; `similar` (word diff), `unicode-normalization`, `csv`, `rust_xlsxwriter`.

**Spec:** `docs/superpowers/specs/2026-11-19-fileodyssey-toolkit-design.md` §5.2, §6.3, §7; roadmap M5.

## Global Constraints
- PDF as a *target* is M7 (Typst/webview print); PDF as a *source* is M6.
- Report: words, headings, paragraphs, tables, table cells, images, links, footnotes; text similarity; ⚠ if similarity < 99% or any count drops (spec §7.1).
- Round trips MD→DOCX→MD and HTML→DOCX→HTML: normalised text must match (§7.3).
- Corpus gate: metrics never below stored baseline (§7.2).
- Outputs never overwrite inputs; text targets with images become a folder `name (converted)/` holding the file and `media/`.
- The app works offline: no network in Pandoc (wasm has none) and none in the worker.

## Review Focus
1. Pandoc failure (bad input, unknown format, Haskell exception) → clear job error, worker recreated, next job works.
2. Job cancelled mid-conversion → the worker is terminated and the next job still runs.
3. Non-ASCII file names and Bengali/RTL text survive every pair.
4. Large inputs (≥20 MB DOCX with images) don't freeze the UI (worker) and don't time out silently.
5. Pairs where Pandoc has no reader for the output (TXT) still get a meaningful report.
